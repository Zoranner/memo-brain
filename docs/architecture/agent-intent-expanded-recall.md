# 智能体意图扩展检索

## 背景

面向智能体的记忆检索不能只依赖用户原话。用户原话经常只表达“想完成什么”，不会完整表达“完成这件事需要遵守什么”。

例如：

- 记忆：`Rust 修改后必须执行 cargo clippy --all-targets --all-features -- -D warnings。`
- 请求：`帮我实现一个功能：xxxxx`

如果只用原始请求做检索，向量检索和 BM25 都可能漏掉这条记忆，因为请求里没有 `Rust`、`cargo`、`clippy`、`修改后`、`检查` 等词，也没有直接表达“完成前验证”这个意图。

同样的问题不只出现在代码项目里。一个面向儿童的对话玩具也可能有这类记忆：

- 记忆：`这个孩子 6 岁，怕黑；睡前故事不要出现怪物、死亡、失踪，要使用安全感元素。`
- 请求：`给我讲个睡前故事。`

原始请求只说明要讲故事，不会自然包含年龄、禁忌、语气、安全边界等检索关键词。

## 问题定义

这类记忆属于隐含执行上下文。它们可能是：

- 约束：不能做什么、必须遵守什么；
- 偏好：用户喜欢的风格、范围和取舍；
- 禁忌：不应出现的内容或行为；
- 术语定义：某个词在当前关系或领域里的具体含义；
- 历史决策：之前已经确认过的边界、根因和反例；
- 完成标准：任务完成前需要验证或满足的条件。

这些内容不一定是流程规则，也不一定属于项目上下文。共同点是：用户不会每次都重复说明，但智能体要完成任务必须主动纳入。

## 设计原则

- `recall` 的默认路径仍保持轻量，不因为意图扩展而默认调用 LLM；
- 意图扩展由上层智能体或调用方完成，不改变 SQLite 真相源、文本索引、向量索引和图扩展的边界；
- 扩展后的 query 应与原始请求一起检索，不能替代原始请求；
- 扩展内容应表达任务画像，而不是编造事实；
- 扩展目标是提高召回覆盖率，让 exact / alias / BM25 / vector / graph 更容易命中隐含上下文记忆。

## 最小实现

最小实现不需要规则引擎，也不需要先调用 LLM。调用方可以把原始请求和固定扩展词拼成组合 query：

```text
原始请求：帮我实现一个功能：xxxxx
补充检索意图：当前用户是谁；当前角色；任务类型；约束；偏好；禁忌；完成标准；相关术语；历史决策；应该避免什么；应该延续什么。
```

对于代码智能体，可以追加：

```text
代码修改；开发规范；禁止事项；语言工作流；格式化；lint；测试；完成前验证；提交偏好；历史边界。
```

对于陪伴或儿童场景，可以追加：

```text
用户画像；年龄；情绪；偏好；禁忌内容；安全边界；语气风格；最近状态；应该避免什么；应该延续什么。
```

## 分层增强

后续可以按复杂度逐步增强：

- 固定扩展词：所有智能体请求都追加少量通用上下文词；
- 模板扩展：根据粗任务类型追加不同模板，例如代码修改、故事生成、陪伴对话、问题排查；
- LLM 扩展：在需要更强语义补全时，由上层显式调用模型生成任务画像；
- 结构化标签：为记忆补充 `constraint`、`preference`、`boundary`、`verification`、`safety` 等标签，再让扩展 query 命中这些标签。

## 非目标

- 不把意图扩展做成默认 `recall` 内部的 LLM 调用；
- 不要求每条记忆都预先写成复杂规则；
- 不用完整规则引擎替代检索；
- 不把扩展 query 的推断结果当成事实写回记忆。

## 示例

代码智能体场景：

```text
用户请求：帮我实现一个功能：xxxxx
扩展 query：帮我实现一个功能：xxxxx；代码修改；开发规范；禁止事项；语言工作流；格式化；lint；测试；完成前验证；历史边界。
可能命中：Rust 修改后必须执行 cargo fmt --all 和 cargo clippy --all-targets --all-features -- -D warnings。
```

儿童对话玩具场景：

```text
用户请求：给我讲个睡前故事。
扩展 query：给我讲个睡前故事；用户画像；年龄；禁忌内容；安全边界；语气风格；最近情绪；应该避免什么。
可能命中：孩子 6 岁，怕黑；睡前故事不要出现怪物、死亡、失踪，要使用安全感元素。
```
